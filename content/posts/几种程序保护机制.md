### **Stack Canaries**

- Purpose: help prevent stack overflow attacks, such as overwriting a return address.
- Mechanism: place a random value, the canary, before the return address in the stack frame. Check it before returning; if it has changed, terminate the program.

###  **NX（No-eXecute）/ DEP（Data Execution Prevention）**

- Purpose: prevent code execution in data regions such as the stack or heap, including injected shellcode.
- Mechanism: mark selected memory regions non-executable so that malicious code written there cannot run.

###  **ASLR（Address Space Layout Randomization）**

- Purpose: hinder attacks that rely on fixed addresses, such as ret2libc.
- Mechanism: randomize the address space, including the stack, heap, and shared libraries, so that an attacker cannot predict exact addresses.

### **RELRO（Relocation Read-Only）**

- Purpose: protect the GOT from modification and hinder redirection attacks such as GOT overwrites.
- Mechanism:
  - **Partial RELRO**: some relocation data becomes read-only, while `.got.plt` remains writable for lazy binding.
  - **Full RELRO**: the entire GOT (Global Offset Table) becomes read-only, preventing GOT overwrites.

### **PIE（Position Independent Executable）**

- Purpose: extend ASLR to the executable itself, making attacks based on a fixed image address harder.
- Mechanism: allow the executable code segment to be loaded at a randomized address instead of a fixed one.

### **Fortify Source**

- Purpose: strengthen compile-time and runtime checks against common buffer overflows.
- Mechanism: insert additional checks during compilation, using checked variants of functions such as `sprintf()` when the compiler has enough information about buffer sizes.

### **Seccomp（Secure Computing Mode）**

- Purpose: restrict the system calls a program can make, reducing its attack surface.
- Mechanism: use interfaces such as `prctl(PR_SET_SECCOMP, SECCOMP_MODE_STRICT)` to allow only a small set of system calls.

### **CFI（Control Flow Integrity）**

- Purpose: hinder control-flow hijacking attacks such as ROP.
- Mechanism: insert control-flow checks during compilation to constrain execution to permitted paths.
